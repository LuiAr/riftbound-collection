# Riftbound Collection Site

This directory is the static Next.js site published to GitHub Pages at `https://luiar.github.io/riftbound-collection/`. `npm run build` runs `scripts/prepare-static-data.ts` and then `next build` with `output: "export"` and `basePath: "/riftbound-collection"`. `.github/workflows/pages.yml` deploys `out/` with `actions/deploy-pages` on push to `main`. Pages must be set to Source: GitHub Actions in the repository settings. The repository can stay private, but a private repository needs a paid GitHub plan for Pages, and the published site is publicly reachable.

There is no D1 database, Sign in with ChatGPT, or server route. Collection reads come from files in this repo. `data/collection.csv` is the current Card Nexus export. `data/exports/YYYY-MM-DD.csv` are the history snapshots. Replacing `data/collection.csv` and adding a dated copy, then pushing, updates the site. The CSV rows are embedded in the static output, so they are published with the site. Deck lists created in the browser are stored in `localStorage`, with download and import of `data/saved-decks.json`.

## Architecture

- The collection page and `/rules/` are static pages. Asset and navigation paths go through `lib/site-path.ts` so they include the GitHub Pages project prefix.
- History compares dated CSV snapshots by exact Card Nexus printing/product ID. Browsing an older snapshot is read-only. Exports and deck counts use the latest snapshot, which is `data/collection.csv` when it matches a dated export.
- `data/exports/2026-09-24.csv` is the earlier supplied export, also kept as `data/initial-inventory.json` for the CSV round-trip test. `data/exports/2026-11-01.csv` is the current scan and matches `data/collection.csv`. Both are published with the site.
- `data/catalog.json` is a compact snapshot of [riftbound-cards](https://github.com/LouisCourrian/riftbound-cards) release `v2026-09-23`; names, rarity, and Riot CDN image URLs originate from Riot's card gallery. Keep attribution visible. The catalog is used for missing cards, art, set/color counts, and foil display. Radiance is not in that snapshot. `scripts/prepare-static-data.ts` refreshes `data/generated/radiance-catalog.json` from the same project's latest `cards.json`. Owned Radiance rows match that file by collector number. A failed download keeps the previous snapshot.
- `data/deck-card-metadata.json` maps catalog codes to full printed names and card types from the Riot-derived [Riftbound-card-data](https://github.com/slimtreble/Riftbound-card-data) export. The deck matcher uses it to distinguish champion subtitles that the compact catalog omits. It accepts quantity-and-name deck lines, groups required and owned copies by full card name, and lists unmatched lines separately. Rune and token exclusions are on by default; section headings and card codes help classify them. Saved deck text, names, and exclusions live in browser `localStorage` and can be committed as `data/saved-decks.json`; their missing counts always use the latest collection file, even while an older version is being browsed. Decks do not estimate prices.
- History compares any two saved imports by exact Card Nexus printing/product ID, showing added and removed printings plus changes to standard and foil quantities. The comparison is read-only and uses the dated CSV snapshots embedded at build time. The one-of-each goal counts regular numbered Common, Uncommon, and Rare catalog cards for the selected set or all sets; it excludes Epic, Showcase, alternate art, over-numbered, promos, runes, tokens, and unmatched inventory-only printings. It is computed from the viewed snapshot and does not write inventory.
- Radiance is in the collection gallery. The printed checklist size in `lib/radiance.ts` is 167, taken from riftbound-cards numbers `001-167` through `167-167`. Numbers 168 and above are over-numbered. When every regular number 1–167 is present, the set filter, collection totals, and one-of-each goal include it: one-of-each counts Common, Uncommon, and Rare cards in that range and still excludes Epic, Showcase, alternate art, over-numbered printings, runes, promos, and unmatched rows. If that checklist is incomplete, owned Radiance rows still show and the set is left out of the goal, so missing numbers are not treated as unrevealed cards the player failed to collect. Rows the checklist does not contain keep the CSV name, print number, finish, quantity, and Card Nexus price, with rarity left unknown and an image placeholder. The Card Nexus `Radiance - Promo Cards` row stays on its own Radiance Promos tile and is not folded into regular number 132. Eleven checklist cards have no domain in the feed, so they are absent from the domain breakdown. Deck matching, deck search, and the need-copies limit still ignore Radiance until deck metadata is reviewed. Do not invent rarity, domains, or Cardmarket expansion ids.
- Catalog-only filters in `app/collection-client.tsx`: Ownership is a four-way toggle (`All cards`, `Owned`, `Missing`, `Need copies`) directly above the cards; On desktop, Set lives in the persistent left rail; phones and tablets use a Set dropdown beside Rarity/printing and labelled search. `Need copies` uses `lib/deck-copy-limit.ts` to show one representative printing per named card below its constructed-deck maximum: 3 main-deck cards, 1 Legend, or 1 Battlefield. It counts all owned printings and sets with the same full printed name together and excludes runes and tokens. The count on the selected printing's badge remains printing-specific, while the need count and progress use the name-wide total. Set, rarity and search narrow which representative cards appear; the owned total remains global. Rarity allows multiple choices, with `All rarities` as reset. An empty rarity selection means all rarities. There is no `Normal cards` preset or separate alternate art and over-numbered exclusion controls. `lib/rarity.ts` centralizes printing classification. Filters do not change saved inventory, summaries, imports, or exports. `Missing` shows zero-copy printings. On phones, Collection insights (including One of each) collapses behind one button so cards follow the filters directly.
- The visual identity is a simple, card-first light theme. Figtree (self-hosted through `@fontsource-variable/figtree`, imported in `app/layout.tsx`) is the only typeface; headings use heavy weights in sentence case, with no uppercase eyebrow labels. The logo orange (`--accent`, #F07F00) is the single accent: active tab, primary button (dark text on orange), progress fills and the foil badge, with `--accent-ink` for orange text. Neutrals are one cool night-blue family (`--ink`, `--muted`, `--bg`, `--surface`); do not add warm greys or pure white. Corners follow one rule taken from the printed cards: card art and frames keep the printed card shape (744 × 1039 with rounded corners, `--card-radius`) and never clip card corners, which carry the energy cost and Might; buttons, inputs, dropdowns and toggles use `--radius-control` (12px, with 8px inner segments); panels and dialogs use `--radius-panel` (20px); small chips and the quantity badge are fully round. Icons come from `lucide-react` only. The quantity badge sits in the bottom-right corner over the artist and copyright line. Colours, fonts, radii and Riftbound domain colours are CSS variables at the top of `app/globals.css`; reuse them rather than adding new hex values. Domain colours (Fury, Calm, Mind, Body, Chaos, Order, Colorless) mark card tiles, the card view and the By domain breakdown. The Set Atlas layout in `app/atlas.css` keeps desktop navigation, set selectors, and account controls in a fixed left rail. The main canvas leads with Import and Export, an unboxed selected-set summary beside One of each, then ownership/search/rarity controls and a five-column full-art gallery. By domain and Card values remain in the collapsible Collection insights panel, opened from the rail; All sets remains available. Below 960px the rail becomes top navigation, the Set dropdown returns, and Collection insights has its own disclosure. Below 720px navigation and cards each use two columns. Players with no import see a welcome panel with the only Import button. Motion is CSS only (view fade, toggle slide, progress fills, tile lift, dialog open) and switches off under reduced motion.
- The quantity badge shows total copies of that printing and gains a foil finish (orange badge and prismatic card frame) for owned Rare, Epic, Showcase, or over-numbered printings, or when an imported row explicitly records foil copies. The small domain-coloured bars under cards show progress toward the deck copy maximum across printings of the same name. Proving Grounds is excluded from rarity-based foil inference because its box printings are nonfoil. Keep the badge's treatment tied to reliable catalog rarity or the imported finish, never to image appearance.
- A card tile opens a larger, keyboard-accessible card view with its inventory count, rarity label, and a prominent per-card estimated price with standard/foil breakdown when available. Rarity filters, card tiles, and details use text rather than separate rarity icons; the printed card art still shows its own rarity marking. The owner-supplied orange logo is `public/riftbound-logo.png`; the header, welcome panel, card placeholders and icons use resized copies of it (`riftbound-logo-96.png`, `icon-64.png`, `apple-touch-icon.png`), so regenerate those if the logo changes.
- `scripts/prepare-static-data.ts` fetches Cardmarket's public Riftbound product catalogue and daily price guide (game 22) at build time and writes `data/generated/market.json`. `avg7` and `avg7-foil` are recent EUR sale averages. A guide older than three days is still embedded, and the page shows that it is stale. Only a unique Cardmarket product matched to a unique catalog name within a known set is quoted; unmatched, ambiguous, and inventory-only extra printings remain unpriced. The card view also withholds base-product estimates for over-numbered, alternate-art, and Showcase printings. The collection view shows price coverage and uses quoted owned finishes for the most valuable card. Keep price estimates separate from saved inventory and avoid representing partial coverage as a total collection valuation.
- `lib/collection.ts` parses and exports the Card Nexus CSV format and compares full snapshots. An import replaces the prior snapshot; it does not add quantities to it. The importer preserves every source column for round-trip export.

## Deck builder

The Deck builder uses the latest inventory file, full playable identities across all printings, and temporary additions that never write inventory. Paid AI generation is not available on the static site. Find collection decks, review, and upgrades run in the browser from the embedded prices, exchange rate, and rules check. Competitive defaults to Akali and 1,000 SEK; fun mode locks selected owned favourites and offers compatible Legends. The source pool in `data/builder-references.json` has 57 distinct full lists for 34 Legends, including all eight official Los Angeles finalists, lower-placing official featured lists, reported results and community builds. Identical printings/uploads are merged with source aliases. The historical Wuhan claim remains in the saved research bank but is not imported into generation. All original 12 reference IDs are retained for saved outputs. All 57 pass the Standard 1v1 validator. Sources are curated, not automatically scraped. Generation selects up to 20 legal references dated after the current ban epoch and within 90 days; collection dates are labelled explicitly when exact updates are unknown. Do not claim competitive quality merely because a Legend has a reference.

`data/builder-cards.json` combines the existing catalog with Riot gallery type, supertype and champion tags, Riot-derived full names and printed text, and official English errata checked 2026-10-07. Radiance stays out of deck generation and legality checks. The validator handles 40 Main Deck cards including the chosen champion, 12 runes, three distinct fields, domains, chosen Champion/Signature tags, three-copy limits across main/chosen/sideboard, three total Signatures, and a maximum 10-card sideboard. Unsupported special deckbuilding exceptions and event addenda require review. Rule snapshots are clearly dated. The static build rechecks Riot's hub and fails closed when dates, document links or ban entries change. On 2026-11-01 the hub still showed the September 18, 2026 constructed ban list, with new core and tournament PDF links, and those links were pinned.

`lib/server-prices.ts` retains existing collection prices and adds playable-name offers. Multiple Cardmarket variants are accepted only when their full name, set and metacard identity agree; the exact printing is marked unverified. Cheapest available guide finish/product estimates are compared across equivalent playable products, prices older than three days are rejected, FX older than seven days is rejected, and shipping is excluded. An unknown price cannot validate a purchase budget.

The previous `/api/builder` path required ChatGPT authentication and an `OPENAI_API_KEY` Site secret. That server path is not part of the static site, so the Generate deck action stays disabled. The retained implementation notes below describe the last server generator: it used GPT-6.1 Sol for strategy; simple choices are deterministic and cost zero tokens. Jev and other cheap-model providers are not connected. The monthly token-estimate limit is 100 SEK and each request reserves at most 10 SEK using conservative input-token bounds and the output cap. Reservations are atomic; uncertain service usage remains reserved. The limit excludes taxes and payment fees. AI output is never accepted before deterministic validation; failures still count measured token charges. Accepted outputs and explanations are saved to the account, but counts and current prices are always recalculated on display. Until a key is configured, the generation action is visibly disabled. The simplified UI shows champion, optional purchase budget, Generate deck, and one result with Save deck. Fun favourites and temporary counts live under More options; strategy, sources, purchase prices and AI usage are collapsed. Explicit saves use browser storage, with the full sectioned export visible in Saved decks and Deck matcher. `lib/saved-builder-deck.ts` restores all quantities and sections without hiding saved lists that need a legality review. Saved deck ownership uses the latest imported collection; temporary extras are not persisted as inventory. All unfinished, failed, rejected and completed generations remain in a paginated generation inbox until explicitly kept or deleted. Keep saves one validated version idempotently to saved_decks and removes it from the inbox. Activity and rejection details stay collapsed. Favourite selection uses an owned-printing image dialog with name, rarity/printing, set and domain filters; special printings are the default. Favourite IDs remain playable identities, with printing codes used only to prefer art. Generation POST uses an idempotency key and returns after the background provider request is acknowledged. OpenAI Responses uses background:true, store:true and one Conversation per generation, whose completed output has no response TTL. Server-side context, IDs, raw output, status, and timestamped events are persisted in D1. The initial submission is attached to the request execution context's waitUntil; slow or interrupted submissions retain a visible recovery state. The AI continues with the browser closed; deterministic validation and copying the final output into D1 occur on the next authenticated status poll or return. Polls use short leases and atomic settlement to prevent duplicate billing. Response records that expire, or submissions whose response ID was not saved, recover completed assistant output from the Conversation. Exact usage is then unavailable, so the original reservation is charged as a labelled conservative estimate. Unknown usage remains reserved. Delete removes provider Conversation items, the Conversation and Response, and local output/context/events, retaining the billing ledger. Durable stage events drive the four-step visual. Logs contain stage, generation ID, provider request/error IDs and short safe messages, never keys or prompts. No queue, scheduled worker or webhook is configured. Spending and account isolation are unchanged.

`lib/deck-quality.ts` groups reference profiles by strategy, prioritizes official event evidence by overall placement, and measures exact raw-draw access and printed Energy distributions. Engine annotations are reviewed judgments scoped to the known Akali, Diana Hwei variants and separate Irelia tempo/Heron strategies. They are not inferred from frequency or applied to every Legend. The model must assess unreviewed engines from supplied card text. Every accepted output gets a quality snapshot; request context preserves the exact supplied reference snapshot so future updates do not rewrite background generation evidence. Evidence and consistency stay collapsed in the simple UI. No full-game simulator, win-rate prediction or automated resource/sequence engine is implemented.

`lib/strategy-feasibility.ts` now compares actual reference packages before generation. It costs confirmed missing copies across equivalent printings, separates full-reference readiness from reviewed core readiness, preserves engine quantities per reference, and records optimistic single-copy floors without claiming they are playable. Unknown prices block confirmed affordability. Strategies without core annotations remain eligible for AI assessment. Owned-only and budget recommendations are separate and prioritize package readiness before source evidence, without using a card-match percentage. Core costs include the Legend, chosen champion and favourites; full-reference costs include sideboard. Guidance is compacted for the prompt while the full generation-time snapshot is retained. Starting-point costs stay under collapsed evidence details. Old jobs without feasibility snapshots remain supported.

Exported requests must stay outside public assets, and real paid batches must preserve spending limits.
